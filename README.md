# 启航 · 独立站 AI 创业与经营中台

面向从零创业的经营工作台。支持项目条件、阶段闸口、岗位任务、商品验证、内置商店、审批、订单与复盘。原始目标见 [产品方案](docs/PRODUCT_SPEC.md)，实际验收范围见 [交付记录](docs/IMPLEMENTATION.md)。真实商业能力仍取决于经营资料、模型及支付等外部授权，不能将测试数据当经营成果。

## 启动

Python 3.12+，默认 SQLite，不需要第三方运行依赖；PostgreSQL 需要安装驱动：

```sh
python3 -m pip install -r requirements.txt
python3 server.py
```

默认监听本机 3000 端口。`PORT` 改端口，`APP_DB` 指定 SQLite 文件。公开监听需设置 `APP_HOST=0.0.0.0` 和至少24个字符的随机 `APP_ACCESS_TOKEN`，否则拒绝启动。不能把访问密码放在代码或聊天中。

反向代理的 HTTPS 地址由 `APP_PUBLIC_ORIGIN` 指定，Render 默认使用 `RENDER_EXTERNAL_URL`。`/api/health` 检查服务与数据库就绪情况，不暴露项目资料。

## 第一次使用：还没有独立站

1. 管理员在登录页留空账号，使用部署访问密码登录。
2. 新建项目，记录预算、市场、资源、目标与未知条件。在工作台生成并验收启动卡。
3. 在“商品与供应”维护机会方向、商品SKU、供应商、有效报价、实物样品和风险档案；上传文件后用文件ID作为来源引用。
4. 机会确认后申请进入验证阶段。正式销售准备要求有效报价、样品通过、正常及保守成本完整且贡献为正、风险已处理。
5. 没有站点时，在“知识与连接”配置内置商店。填写商品售价、库存、配送和退换政策，默认选择“测试”。
6. 在工作台提交“站点发布”审批，对象填写页面显示的项目ID。审批通过后，在“知识与连接”发布商店并打开公开链接。
7. 公开商店支持商品展示、购物车和测试下单。本地测试订单使用 TEST- 前缀，不收款、不发货、不计真实收入。
8. 订单、客服工单、实验和费用可在相应页面记录。复盘事件会产生跟进任务。自动派工需要显式开启；成果、重大决策与外部动作仍需验收或审批。

## 账号与隔离

管理员可在“知识与连接”创建独立账号，每个账号拥有独立工作区，不能读取其他账号的项目、文件、导出、订单或审批。旧项目归管理员工作区。账号密码使用 scrypt 哈希，登录会话持久化并在24小时后过期；禁用账号会撤销会话。

管理员访问密码来自服务端配置，独立账号登录时同时填写用户名。管理员入口保留用于管理工作区，不提供公开自助注册或密码找回邮件。Cookie 使用 HttpOnly、SameSite，HTTPS 下使用 Secure。不把原始密码写进 Cookie。

## 模型与岗位执行

服务端读取 `AI_API_KEY`（或已有 `OPENAI_API_KEY`）、`AI_MODEL`、可选 `AI_BASE_URL`（默认 `https://api.openai.com/v1`），调用 OpenAI Chat Completions 兼容接口。项目启动卡、财务与复盘汇总由程序执行；其他岗位可生成专业草稿。14个岗位已经登记，但模型草稿不等于真实工具执行。

每个项目显式授权0–20次模型调用，每次最多输出2000 tokens；这是次数限制，不是金额计费上限。模型只收到当前项目的资料；客户工单不会默认发给研究和生成任务。没有联网研究、真实图片/视频生成或自动询价能力。视觉岗位当前交付制作方案，不是已生成的15张商品图。

队列、尝试、成果、版本、审批和中断状态保存在数据库。服务重启后，未开始的队列可以继续，已发送的模型请求标为待人工确认，不自动重复扣费。暂停、撤权或资料更新后旧成果不会生效。

## 内置商店与 Stripe

内置商店有三种模式：本地测试、Stripe支付测试、正式销售。所有模式公开前均需对应的“站点发布”审批。修改商品版本或商店配置后需要重新核查并审批。

管理员工作区配置 `STRIPE_SECRET_KEY` 和 `STRIPE_WEBHOOK_SECRET`。独立账号使用 `STRIPE_<账号ID大写>_SECRET_KEY` 和 `STRIPE_<账号ID大写>_WEBHOOK_SECRET`，不会借用其他账号的支付凭据。

Stripe后台将事件发送至 `https://你的域名/webhooks/stripe/<商店ID>`，需订阅 `checkout.session.completed` 与 `checkout.session.async_payment_succeeded`。支付测试只接受 sk_test_ 密钥；正式销售需要 sk_live_、签名密钥、经营资料闸口和真实账户 charges_enabled 检查通过。真实Stripe账户开通、经营者认证和收款授权需要账号持有人完成。

价格由服务端计算；结账操作有唯一标识，超时后只查询，不自动重新创建支付。Webhook核对签名、时效、金额、币种及订单归属，重复事件不会重复建单。支付返回页面不代表支付确认。测试支付生成 TEST-STRIPE- 订单，不计真实收入。正式支付订单也先等待成本和税费核查，不用0冒充已知成本。

当前币种为人民币，运费等需包含在商品定价及政策中；还没有独立运费引擎、多币种、税务自动计算或完整地址履约接口。非测试结账会占用该版商品库存，结果未知时不自动释放；商家需核对支付后通过重新配置与审批调整库存。退款在中台只记账，不执行Stripe退款。

## 可选 WordPress / WooCommerce

没有外部站点可以先使用内置商店。已有 WordPress / WooCommerce 时，先登记连接，管理员配置 `WP_SITE_URL`、`WP_USERNAME`、`WP_APP_PASSWORD`（官方应用密码），再验证权限。独立账号前缀为 `WP_<账号ID大写>_`。

适配器通过官方REST接口验证当前用户，分页读取WooCommerce商品与订单（每页最多20条，界面可指定下一页）。导入只保留必要商品/订单字段，不获取客户地址和联系资料；未核对金额口径和成本的来源记录不直接计入收入。

SEO文章发布需文案档案与针对该档案的已批准审批，使用唯一slug和操作台账。超时与进程中断后只允许查询外部结果，不自动重复发布。外部服务凭据只从服务端环境读取；拒绝不安全地址、私有网络地址和HTTP重定向。未实现广告平台、社交发布、物流和客服外部接口。

## 持久化与迁移

SQLite 数据默认在 `.data/app.db`。免费Render实例的本地文件可能在重启或部署时丢失，不能作为长期经营数据库；页面显示临时数据提示。配置 `DATABASE_URL` 后使用PostgreSQL并保留任务、审批、会话和文件。应使用服务商提供的安全连接方式，公网连接按服务商要求设置TLS与可信CA，不关闭验证来排障。

SQLite迁移至空PostgreSQL：停止应用写入，安全配置目标 `DATABASE_URL`，执行：

```sh
python3 tools/migrate_sqlite.py --source /安全位置/app.db
```

工具先备份源库，再事务复制数据；目标非空时拒绝覆盖。原账号哈希保留，登录会话不复制。核对项目、审批与日志后再启动目标服务。源库和备份必须保留，直到恢复检查完成。PostgreSQL生产备份使用服务商快照或 pg_dump，并验证恢复。

## 财务口径

订单净收入、广告前贡献、营销后贡献及经营结果分开计算。正常/保守预测与实际口径分开保存。订单退款按累计记录更新一次；营销费用来自活动已记录支出，期间费用单独记账，不重复录入订单成本或广告支出。费用凭据ID防重复，估计项另列。外部导入、测试订单和待核查订单不自动成为经营成果。

## 测试与部署

```sh
python3 -m unittest discover -s tests -v
node --check web/app.js
node --check web/business.js
node --check web/shop-ui.js
```

设置专用 `TEST_DATABASE_URL` 可对真实PostgreSQL运行同一测试套件；每个测试使用隔离schema。测试会忽略生产 `DATABASE_URL`，不会写入生产数据库。

浏览器测试需要Playwright与Chromium：`tests/browser.cjs` 验证基础页面，`tests/business-browser.cjs` 自动启动独立测试实例，验证结构化业务、商店发布、购物车、测试下单、文件、审批与独立账号隔离。本云环境可使用 `NODE_PATH=/opt/codex/cua_node/lib/node_modules`。

仓库提供 Dockerfile 和免费Render预览蓝图。Render的账号授权与环境变量由用户在托管平台填写。真实模型、站点和Stripe均未在本环境获得凭据，当前外部集成测试采用受控响应，不能据此宣称真实经营已经跑通。

正式销售时，项目市场必须能确定为单一发货国家码（例如US）；托管结账据此收集配送地址。客户地址保留在支付服务商系统，中台不默认发送给AI。当前履约仍需商家在支付服务商后台核对地址并人工处理，不宣称已经自动发货。
