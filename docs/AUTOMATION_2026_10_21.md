# 默认自动启动修正

用户要求输入需求后直接开始。此前 quick_start 只将启动卡排队，启动卡验收、自动派工、研究权限和方向选择仍需点击，行为不符合要求。本轮修正：

- 网页新建项目默认开启自动派工，启动卡由程序自动交接，不确认未知事实。
- 老版没有自动模式标记的项目升级后自动接续；暂停、结束状态保持停止。关闭自动派工后不会被每次轮询重新开启。
- 自动准备一次有期限、有次数的研究读取授权；模型配置完整且有费用估计时，在剩余项目预算内预留最多20次调用，不无限续费，不恢复已撤销或耗尽的模型授权。
- 有实际来源的候选方向自动进入内部验证并生成任务；满足阶段闸口后自动进入下一阶段，内部岗位有可复核产物时按原有验收规则自动交接。
- 模型未连接、费用未知、预算不足、执行失败和结果未知明确显示阻塞原因。未知付款请求不自动重发。
- 移除首页要求用户点击“确认启动卡”的重复引导。

验证：SQLite和真实隔离PostgreSQL分别运行75项测试，各74项通过、1项后端专用测试跳过。新增用例覆盖无确认自动启动、研究只排队一次和模型未配置／撤权不造假授权。浏览器使用受控提供商响应，仅提交一句需求、不点击启动卡、研究或方向选择按钮，即产生来源、自动方向与验证计划；继续原商品素材与移动端流程通过。前端语法与Git差异检查通过。
